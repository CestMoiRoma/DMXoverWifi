# Scenes

[Wiki index](../../WIKI.md)

A scene is a named look: a list of channels and the value each should take.
Recall it and every channel in the list goes to its value at once.

## Building one

The reliable way is to build the look on the rig and then name it. Set the
fixtures to what you want with the ordinary controls, open the Scenes page,
create a scene and press **Capture the live look**: every channel currently
holding a value lands in the scene. Naming what you can see beats typing numbers
into a form, and it is how the feature is meant to be used.

The search bar in the scene editor filters channels by fixture and channel name,
which is what makes a scene over thirty channels bearable to edit afterwards.

## What a scene stores

Steps, each one a channel uid and a value:

```json
{
  "id": "scn-a8d2f9",
  "name": "Alert",
  "description": "",
  "steps": [
    {"uid": "ch-env1-1", "value": 255},
    {"uid": "ch-env1-2", "value": 255}
  ],
  "labels": []
}
```

**By uid, never by address.** A rig gets readdressed and fixtures get edited; a
scene that remembered "address 12" would afterwards light the wrong lamp without
saying so. Looking the channel up means it either finds it or reports what it
could not place.

A channel absent from a scene is left alone rather than being set to zero. A
scene is a set of instructions, not a snapshot of the universe, so two scenes can
own different parts of a rig and be recalled in any order.

## Playing one

- The play button on the card.
- `POST /api/scenes/<id>/play`, which answers `{"ok": true, "missing": []}`.
- MQTT: any payload to `<base_topic>/scene/<id>/set`. Home Assistant sees each
  scene as a scene entity and sends `ON`.

`missing` lists the uids this board does not carry. That is empty for a scene
made here, and populated for one brought in from another rig, so a scene doing
less than it claims says so rather than failing quietly.

Deleting a fixture drops the steps that pointed at its channels, so scenes do
not accumulate references to nothing.

## In Home Assistant

Every scene is published as a `scene` entity on discovery, grouped under one
device named for the board. They are stateless by nature: a scene is something
you fire, not something that is on, so there is no state topic and nothing to
keep in step.

Deleting a scene withdraws its entity, rather than leaving it in Home Assistant
for ever pointing at something that no longer exists.

## What a scene is not

There is no fade time, no chase and no timeline. A scene is a jump: every
channel goes to its value on the next DMX frame.

That is a deliberate limit rather than a missing feature. Everything in the
timing budget here is best effort, so a fade generated by this board and streamed
channel by channel would be visibly uneven the moment the network hiccuped. A
fixture's own built-in fade, or a real desk, does that job properly. See
[Timing and latency](timing.md).
